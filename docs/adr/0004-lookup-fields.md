# 查词显示哪些字段，以及用法内容不写入词表

日期：2026-09-28

状态：已接受；用户明确要求以后调整字段时先回看本文

## 背景

原来的 Explain 只让 AI 用 1–3 句英文解释选区。用户用它的初衷是理解英文语境、学会使用单词，希望多一层中文解释，并提供"用法"之类的内容。

从第一性原理看，一个词从"看懂"到"能用出来"缺的东西，按价值排序：

1. 这里是什么意思：当前语境义、整句意思（解决看懂）
2. 这个义项怎么搭：常用搭配和句型。中文母语者最常错的是搭配和介词，不是词义
3. 为什么说话人选这个词：语感和语域，决定以后在什么场合敢用
4. 换一个场景的例句：只在一个句子里见过的词很难迁移
5. 易混词：只有少数词真的需要

## 决定

查词弹窗显示：

- 词义层（同 danzi 快查）：当前语境义、原句意思、词性、简明英文释义、领域/场景
- 用法层：常用搭配/句型（1–3 条）、语感/语域（一行）、一个换场景例句（附中文）；易混词只在 AI 判断确实容易混时出现

不显示：音标（看视频时已经听到）、词根词族、原句语法拆解、多个义项罗列。这些当场用不上，还会把弹窗撑成一篇文章、打断看视频，留给 danzi 深析。

加入词表时**只写词义层**，用法层只在弹窗里出现。

## 取舍

- 用法层写进词条：要改 `for_obsidian` 的 `vocabulary_store.py` 和 `word/DESIGN.md`，快查会和深析的"搭配与语域""补充例句"两个模块重复，快查与深析的边界变模糊。danzi 仍在设计中，现在动它的格式等于在没定型的设计上再加一层。
- 用法层放在词条的单独小节、深析时替换：可行，但同样要改 danzi，留作以后的选项。
- 保留用法层的理由：它在弹窗里当场就起作用；值得反复看的词以后走深析，内容还会经过权威来源核查，比 DeepSeek 当场生成的更可靠。

## 什么时候该重新考虑

出现以下任一情况时，回看本文再调整 `prompts/explain.md` 或词条格式：

- 经常想回看弹窗里的用法内容，而词条里没有
- 某一项和其他项重复，或者太啰嗦、读不过来
- 某一项几乎从来不看
- danzi-skill 的快查/深析格式定型，或者改了
